## Nit
1. **The loading/error placeholder looks different from the blank-file placeholder.** The blank-file branch draws a 24dp icon tinted `onSurfaceVariant`. While loading, and on error, `AsyncImage` draws the same vector untinted (`#FF000000` in `ic_image_placeholder.xml`) and scaled by `ContentScale.Crop` to fill the whole 64/96dp box. The gallery already behaved this way, but now it shows on every card while it loads, and for missing files. **Fix:** drop `placeholder`/`error` and use `SubcomposeAsyncImage` with `loading`/`error` slots that draw the same centred, tinted `Icon` as the blank branch. Do not use `colorFilter` on `AsyncImage`: it would tint the photo too.
2. **Failures are silent.** `removeImageLocation` returns `false` with no trace, so a HEIC that keeps its GPS cannot be seen in Logcat during testing or the defence. **Fix:** in the `catch`, add `Log.w("FileUtils", "GPS EXIF not removed from $path", e)` (name the exception instead of `_`). The behaviour stays Q2.
3. **The privacy step lives in one implementation only.** The Firebase repository will replace `LocalTicketsRepository`, and the `TicketsRepository.reportTicket` contract does not mention the step. **Fix:** add one line of KDoc on `TicketsRepository.reportTicket`: "Implementations must remove photo GPS EXIF (FileUtils.removeImageLocation) before the ticket becomes visible." The docs plan already covers overview.md.
4. **XMP location is not covered.** `ExifInterface` clears EXIF GPS only. Some cameras also write `exif:GPSLatitude` in an XMP packet (`TAG_XMP`). **Fix:** no code change for now. Add it as a known limitation, next to video metadata, in decision 0006 and in the report's improvement notes during the docs phase.
5. **The card's description says "photo" for a video.** When the first attachment is a video, the card thumbnail still reads "Ticket photo" / "Fotografia da ocorrência". **Fix (optional):** add `ticket_thumbnail_video_description` (EN "Ticket video", PT "Vídeo da ocorrência") and choose by `attachment?.type`. Or leave it and accept the current text.
6. **A small duplicate in `TicketThumbnail`.** The `attachment == null` branch repeats the placeholder `Icon` that `AttachmentImage` already draws for a blank file. This is acceptable, because `AttachmentImage` takes a non-null `Attachment`. **Fix (optional):** leave it as is, or mention it at the defence as a deliberate "no attachment vs no file" distinction.
