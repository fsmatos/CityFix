  - f704087 `fix(D-011): check the e-mail sync once per account value` (S1). The reviewer's fix: a local `emailChecked` flag inside the `flatMapLatest` branch, so only the first `Found` snapshot per account emission is compared. Why it is safe: a new account value comes only from a sign-in or `reloadAccount()` (which calls `getIdToken(true)`), so the one write carries a fresh token; a later snapshot (another device's sync, or the cache reverting a refused write) never triggers a write, which removes both the two-device ping-pong and the write/reject loop. A `retry()` also restarts the listener and so checks once more (one write, not a loop). Residual edge, accepted: a device whose cached account is stale at the moment of a new emission (for example a cold start before its revoked token is noticed) can still write once; the next reload signs it out. The decision 0017 / 0015 amendment line is for the docs phase.
